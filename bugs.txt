CONVERSATION STATE MACHINE LAYER — BUG LIST
===========================================

CRITICAL
--------
C1  modules/conversations/service.py:103-122 (approve, reject)
    Neither method enforces current == AWAITING_APPROVAL. State machine
    permits approve() from AI_PAUSED → AI_ACTIVE and reject() from
    AI_ACTIVE → HUMAN_ASSIGNED. Silent escalation/approval audit on
    unrelated states.

C2  modules/conversations/service.py:124-146 (assign)
    acquire_lock writes before assert_transition runs. Illegal target

    rollback. Same hazard for any future illegal `* → HUMAN_ASSIGNED`.

C3  modules/conversations/service.py:185-195 (force_transition)
    HUMAN_ASSIGNED → AI_ACTIVE (or any away from HUMAN_ASSIGNED) does not
    release the lock. Conversation ends with stale locked_by, breaking
    the lock invariant.

C4  modules/conversations/service.py:_transition + db/session.py
    Docstring + docs claim "atomic with the state write". Reality:
    update_state and audit append both flush(), neither commits.
    get_db_session has no commit/rollback discipline. Audit row can
    reference a not-yet-committed state; on exception both are lost.

C5  app/core/events.py:28 (pre-existing, now reachable)
    logger.info("event_emitted", event=event, ...) collides with
    structlog reserved kwarg → TypeError on every transition emit.
    Tests monkeypatch around it; production path 500s.


IMPORTANT (security)
--------------------
S1  modules/conversations/router.py:119-130 (force_transition)
    No role gate. Any authenticated user can force any transition,
    including target_state=CLOSED on any conversation.

S2  modules/conversations/service.py + router.py
    pause_ai/resume_ai/close/approve/reject/force_transition never
    verify caller holds the lock. resume_ai releases conv.locked_by
    (existing holder), not the caller. Any user can take over any
    conversation.
    [PATCHED 2026-05-15] _assert_actor_holds_lock() added to service;
    called in pause_ai() and close(). resume_ai (stale-lock clearing),
    approve/reject (AWAITING_APPROVAL has no lock), and force_transition
    (admin-only) are intentionally exempt. release_lock() agent_id param
    made optional (unconditional release for close/force/resume paths).

S3  modules/conversations/router.py
    All override endpoints accept any authenticated role. No
    require_role() gating distinguishing agent vs admin.
